## چه ساخته شد؟

1. **HTML نسخهٔ ۸۱** (`web/AtaVision-81.0.0.0-Offline.html`):
   - مبنا: فایل محلی ۱۰.۱.۰.۰ (تنها مبنای در دسترس در sandbox).
   - تغییرات: نسخهٔ `81.0.0.0`، CSP برای بررسی به‌روزرسانی از Pages، اسنیپت
     بررسی به‌روزرسانی آفلاین‌امن (بدون ارسال دادهٔ کاربر).
   - هش: `31dc3fa50f4761dc01013c1c8f48c98b9d2ad7f768204eea0c528c808da93ea8`
2. **Android wrapper** (`android/`): applicationId و origin بدون تغییر، versionCode ‏`81000000`.
3. **Windows wrappers** (`windows/`): WebView2، origin و UserData بدون تغییر؛ پرتابل + نصب‌کنندهٔ Inno Setup.
4. **GitHub Actions**: ‏`build-all.yml`‏ (HTML/APK/Windows/Release) و ‏`pages.yml`‏ (انتشار Pages).
5. **اسکریپت پچ** (`scripts/patch-v81.py`): تبدیل فایل تأییدشدهٔ v80 به v81 (نسخه، AV80→AV81، CSP، بررسی به‌روزرسانی) بدون دست‌زدن به محتوا/ذخیره‌سازی.
6. **مستندات**: راه‌اندازی، مهاجرت، امنیت (فارسی).

## محدودیت‌های صریح

- **مبنای HTML نسخهٔ ۱۰.۱ است، نه ۸۰.** فایل v80 (۱۳.۶MB) در sandbox در دسترس نبود
  (دانلود مستقیم از Drive مسدود بود و دانلود از طریق connector متن را در context می‌ریخت).
  برای نسخهٔ نهایی ۸۱ از روی v80، فایل v80 را پیوست کنید یا آرشیو سورس بدهید و
  `scripts/patch-v81.py` را اجرا کنید.
- **سیستم اشتراک AV81 هنوز در HTML جاسازی نشده است** (مبنای ۱۰.۱ سیستم اشتراک ندارد).
  پس از دریافت v80، پچ AV80→AV81 اعمال می‌شود. ابزار صدور خصوصی در مخزن عمومی نیست.
- **APK/EXE در این محیط ساخته نشدند** (SDK/رانر لازم است)؛ در GitHub Actions ساخته می‌شوند.
  APK در CI با گواهی debug امضا می‌شود؛ ارتقای درجا از ۸۰ نیازمند همان گواهی ۸۰ است.
- **آزمون روی دستگاه واقعی انجام نشد** (Android/Windows/WebView2/نصب‌کننده/Defender/SmartScreen).
  موفقیت شبیه‌سازی به‌معنای موفقیت روی دستگاه نیست.
- **بک‌اند داینامیک ساخته نشد** چون GitHub آن را ندارد. اگر حساب/همگام‌سازی/پنل لازم است،
  هاست جداگانه (مثلاً Cloudflare Workers / Supabase) لازم است — تصمیم مالک.

3. تگ `v81.0.0.0` را push کنید تا Actions هر چهار خروجی را بسازد.
