# امنیت، کلیدها و امضا — AtaVision ۸۱

## کلیدهای خصوصی هرگز در مخزن عمومی نیستند

این مخزن **عمومی** است. موارد زیر هرگز نباید commit شوند:

- کلید خصوصی صدور کد اشتراک و ابزار خصوصی مالک
- رمزها، توکن‌ها و فایل‌های `.keystore` / `.jks` / `.pfx` / `.pem`
- هرگونه secret در لاگ‌ها، مستندات عمومی یا خروجی‌های HTML/APK/EXE

پوشهٔ `private/` در `.gitignore` است. ابزار صدور نسخهٔ ۸۱ را **خارج از این مخزن**
(مثلاً روی دستگاه مالک یا Drive خصوصی) نگه دارید و فقط کدهای صادرشده را به کاربران بدهید.

## ساخت ابزار صدور خصوصی (برای مالک)

1. یک جفت‌کلید امضا (مثلاً Ed25519 یا RSA) روی دستگاه امن خودتان بسازید؛ کلید خصوصی را کپی نکنید.
2. کلید عمومی را در HTML نسخهٔ ۸۱ جاسازی کنید (فقط کلید عمومی در محصول می‌رود).
3. ابزار صدور را از روی ابزار نسخهٔ ۱۳ (`AtaVision-13-Pro-Issuer-Offline.md`) به‌عنوان قالب بسازید،
   اما پیشوند را به `AV81` تغییر دهید و کلید خصوصی تازه را فقط در همان فایل خصوصی نگه دارید.
4. ابزار خصوصی را در Drive عمومی یا GitHub عمومی بارگذاری نکنید.

## امضای Android

- نسخهٔ ۸۰ با گواهی debug سازگار با نسخهٔ ۱۳ امضا شده بود.
- ارتقای درجا مستلزم **همان گواهی** است. اگر گواهی قبلی در دسترس نیست،
  نصب درجا ممکن نیست و باید با پشتیبان JSON مهاجرت کنید — وانمود نکنید تعویض گواهی بی‌اثر است.
- برای انتشار تولیدی، گواهی معتبر بسازید و آن را فقط در GitHub Secrets
  (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEY_ALIAS`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD`)
  نگه دارید؛ هرگز در مخزن نگذارید.

## امضای Windows

- EXEهای نسخهٔ ۸۰ Authenticode معتبر نداشتند. برای نسخهٔ ۸۱ نیز تا وقتی گواهی معتبر
  تهیه نشده، SmartScreen هشدار می‌دهد. ادعای «بدون هشدار ویروس» نکنید.
- Windows به WebView2 Runtime نیاز دارد.
